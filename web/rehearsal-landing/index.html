ICN Rehearsal Node

A local, non-production rehearsal of one governed loop: an organizer reviews, edits, assigns, previews, and confirms a piece of proposed work; a member completes it; every step leaves a receipt.

Non-production rehearsal. Everything here is fictional and runs on local, operator-controlled infrastructure. This is not a pilot, not a production system, and not a live federation.

Run the rehearsal

  • Start a new rehearsal Retires the previous run’s unfinished items and opens a fresh organizer session. Receipts from earlier runs remain — they are permanent process facts.
  • Continue as organizer Review the pending item, edit it, assign it, preview the exact resulting action, and confirm — the confirmation is bound to a digest of exactly what was previewed.
  • Continue as member Opens a fresh, least-privilege member session (the organizer session is never reused or upgraded), shows the assigned action, and lets you complete it.

Sessions start with one click — no account, no credential to paste. Each button asks this appliance for a short-lived, role-scoped session that lives only in the page’s memory.

Receipts and evidence

Receipts appear inside the surfaces where they are produced: the organizer surface lists the process receipts (plan recorded, action applied) and an evidence summary; the member surface shows the completion receipt after the action is completed.

The exportable evidence packet is value-withheld: it proves the process happened without carrying identities or credentials. Verifying an export is an operator step — see Diagnostics below.

What this demonstrates

  • Role-scoped sessions: the organizer can review and confirm but not complete; the member can complete but not review or confirm. Wrong-role attempts are refused.
  • Digest-bound confirmation: confirming with a stale or wrong preview digest is refused; only the exact previewed plan can be executed.
  • Exactly one real action item is created by a valid confirmation.
  • Durable receipts: completion and process receipts survive service restarts and reboots.
  • Secret-free evidence: the export withholds identities and credentials by construction.

What it does not demonstrate

  • No production readiness, no pilot, and no live federation — this is a single local node with fictional data.
  • No real institution: the example domain and member are fictional.
  • No organizer approval and no completed accessibility certification — those are open human gates, not software claims.

If something fails

  • Service unavailable — the appliance VM may be starting; wait a minute and use “Check again”. If it persists, the operator can check systemctl status icnd icn-member-shell icn-demo-session nginx on the VM.
  • Session expired / request refused (401) — return here and start the role again; sessions are short-lived on purpose.
  • Wrong role (403) — expected: organizer-only and member-only actions refuse the other role. Switch roles from this page.
  • Stale preview (409) — expected: the item changed after the preview; re-open the preview and confirm the current digest.
  • Already completed — the assigned action was already completed (completion is idempotent); start a new rehearsal to run the loop again.
  • Full appliance reset (operator, destructive): sudo icn-demo-reset on the VM wipes local state and regenerates per-instance secrets. The browser “Start a new rehearsal” action is the normal reset.
  • Verify evidence (operator): sudo icn-demo-verify --rehearsal on the VM re-checks the receipt ladder and the no-identity/no-credential invariant of the export.
  • Fixture tour (no services) — a read-only, clearly-labeled fixture walkthrough that needs no gateway; useful to separate UI problems from service problems.
